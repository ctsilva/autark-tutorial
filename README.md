# Urban data analytics with Autark

A local, runnable copy of the Observable notebooks of the tutorial
[*Urban Data Analytics with Autark*](https://observablehq.com/@autarkjs/01-urban-data-analytics-with-autark)
(SIBGRAPI 2026). Every example on every page is editable and runs in place, and cells on a page share state
like cells in a notebook.

| Page | Notebook | What it covers |
|---|---|---|
| `index.html` | 01 | Overview, abstract, notebook list. |
| `formats.html` | 02 | Vector and raster data; GeoJSON, WKT, GeoTIFF, OSM XML; OpenStreetMap and open data portals. |
| `db.html` | 03 | `autk-db`: workspaces, loading OSM, GeoJSON, CSV with WKT and GeoTIFF; SQL and spatial queries; heatmaps. |
| `map.html` | 04 | `autk-map`: map lifecycle, layers, OSM and raster layers, thematic color, spatial joins, picking. |
| `plot.html` | 05 | `autk-plot`: scatter plots, histograms, `@transform`, brushing and linked views. |
| `compute.html` | 06 | `autk-compute`: per-feature WGSL computation and render analysis (sky exposure). |

## Extra example: Urbane

`urbane.html` is not one of the notebooks and is not linked from the other pages. It is a full application on top of all four modules: a port of the Urbane use case (`usecases/src/urbane` in the Autark repository), running entirely in the browser. It loads Manhattan from OpenStreetMap (`data/urbane/mnt.osm.pbf`), joins seven urban datasets to neighborhoods, computes sky exposure per road with `ComputeRender` and a weighted score with `ComputeGpgpu`, and links a 3D map to parallel-coordinates and table views. Select neighborhoods and drill down to their buildings, change the weights, and recompute the score.

Needs WebGPU. The first load takes about a minute, because the OSM extract (all of NYC) is parsed in the browser every time. The sky-exposure result is cached in `localStorage` after the first run; add `?fresh` to the URL to recompute it. The pipeline panel at the bottom of the page shows each step and its time.

## Running it

The pages use ES modules and WebAssembly, so they need to be served over http (opening them as `file://` does not work):

```sh
npm start        # python3 -m http.server 8000
```

then open http://localhost:8000. No `npm install` is needed to run the tutorial. Everything is vendored.

Autark Map and Autark Compute (and `urbane.html`) need WebGPU (Chrome or Edge 113+; Firefox Nightly with WebGPU enabled).

## Layout

| Path | Purpose |
|---|---|
| `*.html` | One page per notebook. Prose and all example code live in the page. |
| `tutorial.css` | Page styles. |
| `tutorial.js` | Turns each `<figure class="example">` into a CodeMirror editor with Run, Run all above, Reset and Copy. Cells run in the page and share `ctx`; edits are kept in `localStorage`. |
| `data/` | Sample data, by page: `formats/`, `db/`, `map/`, `plot/`, `compute/`, and `urbane/` (data for `urbane.html`). `data/osm/` holds recorded Overpass answers (see below). |
| `overpass-fallback.js` | `withFallback(fn)`: tries the public Overpass server, and on failure answers the same queries from `data/osm/`. |
| `scripts/record-overpass.mjs` | Records the Overpass answers into `data/osm/`. |
| `vendor/` | Autark 4.1.1 (`autk/`, `autk-db/` with DuckDB's wasm), DuckDB, D3, GeoTIFF and CodeMirror 6. Generated by `npm run vendor`. |
| `scripts/vendor.mjs` | Rebuilds `vendor/` from the pinned versions in `package.json`. |

## Editing examples

An example is a figure with the code in a plain-text script block (highlighted and edited with CodeMirror 6, bundled in `vendor/codemirror.js`):

```html
<figure class="example" data-title="1.1 · Create the database" data-needs="...">
<script type="text/plain">
  const autk = await import("@urban-toolkit/autk");
  ctx.db = new autk.db.AutkDb();   // `ctx` is shared by every cell on the page
  await ctx.db.init();
  return ctx.db.getWorkspaces();   // returned values are displayed
</script>
</figure>
```

Inside a cell you have `ctx`, `out` (the output element), `show(value)`, `table(rows)`, `xmlView(xmlDocument)`, `withFallback(fn)` and `d3`.
Bare imports (`@urban-toolkit/autk`, `d3`, `geotiff`) resolve through the import map in each page's `<head>`.

## OpenStreetMap without the public server

Three cells ask the public Overpass server (`overpass-api.de`) for OpenStreetMap data: `formats.html` 4.1, `db.html` 2.1 and
`compute.html` 3.2. That server is often busy or down, so these cells run inside `withFallback()`: the request is tried live with a
15 s timeout, and if it fails the answer recorded in `data/osm/` for the same query is used instead (and the rest of the cell stays
offline). Answers from the live server are also cached in the browser (Cache API, 7 days), so a second run does not ask again; the server is checked
(4 s) before the first request, so an unreachable server switches to the local files immediately. `/api/status`, which `autk-db` polls and can wait on for minutes, never blocks. Recordings are keyed by a hash of the query text
(without its `[timeout:N]`), so they work as long as the query is unchanged; if you edit a cell's area or layers, that query needs the live server.

- `?overpass=offline` on any page URL skips the live server and uses only the recordings. Use it for classrooms or flights.
- `?overpass=down` pretends the server is unreachable, to see the fallback message.
- To re-record (after changing a query or upgrading Autark), run `npm start` in one terminal and `node scripts/record-overpass.mjs`
  in another, then open and run all cells of `formats.html`, `db.html` and `compute.html` with `?overpass=record:http://localhost:8001`.
  The recorder asks a live Overpass mirror from Node and writes `data/osm/<hash>.json.gz` and `data/osm/manifest.json` (date, mirror, size).

## Updating Autark

Change the versions in `package.json`, then:

```sh
npm install
npm run vendor
```

`vendor/autk-db/` keeps DuckDB's `duckdb-eh.wasm` (about 35 MB) next to `browser.js`, which is where `autk-db` looks for it
when served from localhost. The MVP build (about 40 MB, for browsers without WebAssembly exception handling) is left out.
When served from another host, `autk-db` falls back to jsDelivr for DuckDB.

## Differences from the Observable notebooks

- Imports come from `vendor/` (Autark 4.1.1) instead of `esm.sh`.
- Data files were exported with the notebooks, except for notebook 06: `data/compute/lower_mnt_buildings.geojson` was regenerated
  from OpenStreetMap (64 buildings of Battery Park City with `building:levels`; area and perimeter computed in a local metric projection),
  and the sky-exposure example asks Overpass (with the bundled fallback above) instead of loading the original `lower_mnt.osm.pbf` extract.
- Cells that load OpenStreetMap use `withFallback()`, so they work offline, and they ask for a bounding box instead of `geocodeArea: "New York"` (which resolves to the whole state and downloads a 10 MB coastline).
